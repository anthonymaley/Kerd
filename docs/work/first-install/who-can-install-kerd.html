Kerd · the install test

Kerd's front door: who can install it

The README gives a newcomer two commands. The first works for everybody. The second only works if you have already set up a GitHub key on your machine. Anyone who has not is refused and gets nothing — and setting one up is not part of the instructions. One line changes that: publish the ordinary public web address for the project instead of the private one. Tested: it installs with no key and no setup.

The change, in words

Kerd says about itself today Fetch me from this private address — the kind that only works if you have a key registered with GitHub.
→
Kerd would say instead Fetch me from this open web address — the ordinary public link anybody can follow, with or without a key.
Evidence. Both commands run twice in throwaway profiles, and the machine's own setup verified structurally unchanged afterwards. With a key: installed 0.142.0 from commit ac4d4db, exactly the eight skills the README names, none of the four retired ones. Without a key: step 1 reported SSH not configured, cloning via HTTPS and succeeded; step 2 failed with git@github.com: Permission denied (publickey) and wrote no install record. The repository itself is public and answers anonymously over HTTPS — the closed door is the address in .claude-plugin/marketplace.json, not the repository.
The fix is tested, not assumed. With the public address and no key: installed, all eight skills. With a key: unchanged, also all eight. One obvious repair was tried first and rejected: naming the GitHub project the way the first command names it looks like the tidy fix, and it still failed — installing reaches for the private address anyway unless an environment variable is set, and no newcomer sets one. Only the explicit public address works on its own.
