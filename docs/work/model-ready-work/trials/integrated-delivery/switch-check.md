Synthetic fixture, not a new producer approval. A temporary Git project had a
board-paper work record at Understand, topic 6 of 10, plus unrelated CONTEXT,
TODO and a legacy parked .active-modes line. The standing boundary allowed
research/drafting, not publication, commitments, purchases or a full build
before the unresolved success decision.

The saved pending question was “What would make this a successful result for
you?” Its shown answer proposed that a director could explain the recommendation,
main tradeoff and largest uncertainty after reading the overview. The proposed
assessment was explicitly unconfirmed.

## Save

An independent agent received the candidate Switch and the ordinary request to
save this session. It added an Active Work pointer to existing CONTEXT.md,
linked the work and appended session history beside it. It retained the actual
pending question, proposed answer, source, consequence and next action.
It checked the referenced files and reported local-only state. The main agent
read the resulting context/history and verified that unrelated TODO and the
legacy marker stayed unchanged. No gate, CI, hooks, commits or pushes ran.

## Fresh pickup

A separate agent received only the project, candidate Switch and “Pick up where
we left off.” It recovered the work through the handoff, inspected its relevant
state and reported:

> Understand [NOW] → Shape → Agree → Deliver → Complete

It located topic 6, said success was proposed rather than confirmed, preserved
the project boundary and absence of assessed work, and restored the exact pending
question with its shown answer and source. It did not begin the full build,
make up a user decision, restart intake or ask “Start Conductor?” first.
No project file changed during pickup.

The host's higher-priority question rules required plain text and prohibited
textual multiple-choice options. The agent disclosed that specific conflict and
preserved the question/context without claiming Conductor could override the
host. This test therefore does not prove the preferred bounded Correct/Change
card in every host UI. No active-job references existed in the fixture, so live
job reconciliation at Switch is not proved by this example.
