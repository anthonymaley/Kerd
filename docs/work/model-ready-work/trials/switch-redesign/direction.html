Same session, or move the work?

  1. Just changing consoles

    Reconnect through your existing SSH/tmux connection. The same session keeps running; no handoff or shutdown is needed.

  2. Supported managed build

    The controller that owns the source can save, verify, release it and prepare the exact destination pickup. A failed save keeps that source open.

  3. Ordinary open session

    Switch can save your place. Without control of the actual host, it must say source exit is still needed—not start duplicate work or claim the move is done.

Entry trials and limits. A user-opened laptop session has continued the saved task; automatic remote startup and arbitrary existing-host exit are not implemented.

Carry the work, not the transcript.

  • What we agreed and how success is measured.
  • The current task, evidence and exact next action.
  • Outstanding decisions, failures and job status.
  • Permissions and resource limits that still apply.

Keep durable history reachable. Archive old detail without burying decisions that still govern the work. To and Roll do not tidy away the active task.

A small helper, not a new service.

For Roll and managed To, a local helper owns the fresh CLI workers. It lives outside their context windows; Conductor still directs the build.

No CI, custom hooks or new hosted service. Existing SSH/tmux use stays as it is. Arbitrary already-open app sessions are not assumed controllable.

Now proved locally: a failed push leaves the same source open and blocks destination startup. An authorized repair can retry the save. The controller must stay alive; surviving its crash is not claimed.

What the trials have shown.

  1. 1 · Fresh-context continuity

    Earlier Codex and Claude builds each crossed two automatic transitions. A later Codex build crossed one context-triggered transition. These are distinct observations, not three pressure-driven transitions. Independent continuity review.

  2. 2 · Studio to laptop

    Studio saved and released its owned source. The user-opened laptop session resumed the task; returned files were tested and independently reviewed on Studio. The corrected result passes 33 current and 19 original tests. Evidence and limits.

  3. 3 · Prepared pickup

    Final local entry: 5,518 added input tokens, 3.15% context, 93 seconds; retained meaning independently reviewed. Old local pickup: 32,825, 13.50%, 213 seconds. Both arms used the same already-reorganised snapshot and prepared local sources. Migration, source-selection effort and whole Git-backed pickup cost were not measured. One paired observation, not a general saving. Earlier short summaries lost rules. The corrected display and precise working state stay separate. Results and measurement limits.

Seinn’s original three pickup files totaled 430,854 bytes. Its trial context entrypoint is now 7,156 bytes with history still reachable; the reader used additional files. Those are file sizes, not total input-token measurements. Live Seinn and installed Kerd are unchanged.

Build order and honest limits

Prove fresh-run continuation first. Then implement lean In/Out, join To and Roll, and run independent assessment. A local two-clone rehearsal does not prove a two-device handoff. A manual restart does not prove automatic Roll.

A helper-managed build loop is the first implementation route. Entry from existing interactive hosts still needs investigation. If that changes the agreed experience, the decision comes back to you.
