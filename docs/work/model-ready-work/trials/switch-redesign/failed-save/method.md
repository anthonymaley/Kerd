# Failed save: keep the source, then continue

Scope: two disposable local clones and a local bare Git remote, not GitHub or two
devices. Fresh owned Codex workers, explicit gpt-5.6-sol/high. No native transcript
resume, installed skill change, live project edit or existing user-session exit.
`seed/` retains the byte-identical input from the earlier preview trial. The live
run read those files in their earlier location; the retained runner now reads this
local copy so a future checkout does not depend on ignored external trial output.
The retained runner also skips identical destination reply candidates, matching
Roller; the observed destination returned one candidate, so that compatibility
adjustment has not been claimed as another live replay.

The source improves the previously built preview's label escaping, then pauses
before tests and documentation. `run(hold=True)` returns to the controller while
the same app-server process, loaded thread and named-session lock remain owned.
`ManagedTo` validates every changed checkpoint candidate using the shared checker.
It does not duplicate native event parsing inside a trial observer.

The controller deliberately changes only the disposable remote's push URL to an
unavailable local path. Expected: local commit succeeds, push fails, source stays
alive and idle, and destination preparation refuses before touching its checkout.
The controller repairs that injected path and retries the same returned work,
without a second source turn or new user instruction. Actual remote verification
precedes release; process group and recorded owned children must disappear before
the separate destination restores the exact saved revision and starts fresh.

The destination finishes tests and usage and returns ready for independent review,
not accepted. Controller checks preserve protected inputs, Git history, saved-place
bytes, distinct thread identity and historical failed-attempt counts. The trial
records real events and sanitized results; native session IDs stay in local Git
metadata. The source tool's turn-completion result is not treated as source exit.

An unexpected trial failure explicitly abandons only its disposable owned source
and is recorded as a failed attempt. This cleanup must not be mistaken for the
failed-save product behavior. See attempt-1.md for the invalid-reply failure.

Official basis: [`thread/read` with includeTurns false](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming)
returns a summary including runtime status without resuming or loading the thread.
The check asks the same owned server for the same thread ID and requires idle.
It proves the observed state at that check, not survival after controller/host death.

Unit checks cover failed write, commit, push and remote verification, retained
streams/lock, invalid replies, duplicate candidates, cancellation, uncertain
inspection and cleanup, and destination refusal. Unit fixtures are not live proof
of every failure class; the real run injects a push failure only.
