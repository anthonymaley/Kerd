## Connection and scope

Codex CLI 0.153.4 supplies an app-server stdio mode. It is a local child process,
not a new installed/hosted service. The helper starts a new thread, observes usage,
requests a safe checkpoint through turn steering, then stops/reaps its owned
process group before another worker may run. Native histories are never resumed.
The effective model, project, permissions and event identities are checked.

Protocol basis: [official OpenAI App Server documentation](https://learn.chatgpt.com/docs/app-server),
checked 2026-09-07, and schemas generated by the installed CLI in an isolated
temporary directory. The documented interfaces provide thread creation, latest
usage notifications, steering and completion events. Local schemas establish
the concrete fields accepted by this installation. This does not certify future
CLI versions or arbitrary interactive-host control.

Build model: gpt-5.6-sol, high effort, selected for bounded coding/testing and
prior task evidence. Local OpenAI shared guidance 2026-09 and GPT-5.6 profile
2026-09-05 supply outcome-first framing, native effort and freedom of method.
This is not a claim of optimal cost or a model benchmark. Initial live test uses
an explicitly lowered 26,000-token trigger, not a claim about real exhaustion.

## What will count

- A trigger based on actual latest-request usage, not a fixture piece count.
- Saved useful work, unchanged agreement and preserved failure/evidence state.
- Distinct fresh workers, with previous owned process stopped before continuation.
- Actual deliverable tests and a different-model assessment against the agreement.
- Honest measurement: total host input and cumulative billing are not silently
  relabeled Switch-added context. Missing readings remain unassessed.

Native compaction detection refuses continuation but cannot undo compaction.
Steering is cooperative; a very large tool result may cross the reserve before
the next usage event. No complete automated To or universal no-compaction promise.
