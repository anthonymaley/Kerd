# Live Conductor connection — method

## Question

Can the actual running Roll CLI receive a mid-work To request through its existing
input stream, retain its same source through a failed save, and return a verified
destination for Conductor to continue without another user turn?

This is a local two-clone trial, not Studio → laptop or arbitrary interactive-host
takeover. There is no inbox, service, CI, custom hook or product installation.

## Input and route

`prepare.py` creates a disposable source, destination and bare local remote. The
seed is the earlier reviewed preview deliverable under `../failed-save/output/`.
The new agreement adds useful machine-readable summary output with M1–M4 declared
before execution. Source and destination use gpt-5.6-sol/high on the existing
authenticated app-server route. Selection is based on the earlier bounded code
and handoff results, not price. Prompt basis: local gpt-5-6 profile 2026-09-05,
outcome first, explicit authority/evidence, method left to the model. This run
does not establish optimal prompting or an effort comparison.

The real command was `roll.py --context-aware --control` with the fixture source,
agreement.md and place.json, launched with the host's PTY execution option.
Conductor retained that live execution handle and sent the JSON To request after
the worker's first command activity. No observer called ManagedTo directly.
`received` and `saving_place` preceded the safe checkpoint. No low context
threshold was used; this is externally requested To, not context-pressure proof.

The fixture deliberately gives origin an unavailable local push address. After
the source reached its checkpoint the save failed and the owner remained held.
Conductor read the recorded error and state, checked that the destination stayed
at its initial revision, requested status through the same open channel, repaired
only that push address, then sent retry through that same handle. No model rerun,
new controller or user approval occurred during recovery.

After the CLI returned handed_off, Conductor immediately started ordinary
context-aware Roll in the prepared destination under the unchanged agreement.
The trial collector verifies distinct native identity privately, cleanup, exact
Git revision and retained failure history. It saves selected results and prompts,
not private session IDs. The Claude artifact assessment uses a fresh opus/high
read-only job, with the original agreement and actual deliverables. Its prompt
uses the local Opus/shared 2026-09 guidance: a bounded assessment, descriptive
sections and no prescribed reasoning script. Test execution remains the
controller's responsibility because that reviewer route has no shell.

## Interpretation

The source attempted one combined patch, which failed on a documentation context
mismatch and applied no code changes. Its checkpoint says so. This proves that
the move can carry analysis and an unfinished attempt without manufacturing
artifact progress; it is not a proof of transferring partly edited source code.
The earlier held-save trial covers that separate case.

One local successful run does not prove a remote launcher, crash survival, complete
compaction prevention, optimal speed/cost, whole-pickup context cost, or exit of the
person's current interactive session. Cancellation is cooperative: synchronization
already underway may update a destination checkout, but must not launch work.
