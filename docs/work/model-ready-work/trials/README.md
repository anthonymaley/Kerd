## Shared trial flow

```text
Real rough request
       |
       v
Fresh: ask the outcome question / Active: resume the saved edge
       |
       v
Read relevant context, then continue guided interview and challenge
       |
       v
One visual direction approved
       |
       v
Assess bounded jobs
       |
       v
Choose capable model + effort and explain why
       |
       v
Prepare model-specific prompt + prove coverage
       |
       v
Build <-> peer review <-> prove <-> improve
       |
       v
Every original measure passes independently
       |
       v
Trial completion point reached
```

## Shared success measures

| ID | Measure | Pass condition | Evidence |
|---|---|---|---|
| T1 | Natural intake | Each trial begins from the producer's rough request, not a completed form | Initial request and question record |
| T2 | Context at the right time | Conductor first obtains the person's intent or resumes active work, then reads relevant records before follow-up questions | Initial request, context-source record, saved edge and questions |
| T3 | Understandable approval | The producer can approve one high-level view of outcome, connected parts, flow, measures, guardrails, authority, resources, and stopping point | Approved visual direction |
| T4 | Appropriate routing | Every job records capability, consequence, complexity, tools, uncertainty, proof needs, selected provider/model/effort, and rationale | Dispatch records |
| T5 | No underpowering for cost | Every selected model is eligible on capability and evidence before efficiency is considered | Eligibility and selection record |
| T6 | Model-ready preparation | Claude and OpenAI jobs use the applicable locally versioned official guidance | Prompt metadata and guidance versions |
| T7 | Preservation | Every approved outcome, measure, boundary, authority rule, context obligation, and stopping condition maps into the prepared job or an enforced mechanism | Coverage reports |
| T8 | Autonomous work | After direction approval, no routine producer input is required | Intervention log; any intervention tied to a contract-level decision |
| T9 | Independent proof | A peer or different model judges every original measure from admissible evidence | Measure-to-evidence review |
| T10 | Meaningful recovery | A retry responds materially to the prior finding; three failed approaches against one measure return routing control to Conductor | Attempt records and escalation, if exercised |
| T11 | Honest completion | Both trial-specific completion contracts pass, with limitations and unresolved work visible | Final outcome reports |
| T12 | Useful telemetry | Elapsed time, model/effort, turns, tool calls, interventions, retries, evidence, and resource use are recorded | Trial run records |

There is no duplicate run through current Conductor. These trials can prove that
the proposed process works and establish observed performance. They cannot claim
causal improvement over the current process without a comparable baseline.

## Learning stop

Move quickly. Stop the MVP when both trial completion contracts pass and the
evidence is sufficient to decide the smallest responsible Kerd implementation.
Do not expand either trial merely to make its package exhaustive. Record valuable
continuations separately so the work can continue after the Kerd decision.

## Adoption output

The trial conclusion must recommend, with evidence:

- what to build in Kerd first;
- what remains manual or experimental;
- which model profiles and effort rules earned retention;
- whether the guided interview and visual approval need revision;
- whether session routing is reliable enough to depend on;
- whether the general repository-based claim survived both domains;
- how the existing Drive/Conductor ownership decision must be reconciled.
