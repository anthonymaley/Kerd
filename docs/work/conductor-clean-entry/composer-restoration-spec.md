`54c28cd:skills/conductor/SKILL.md` (v0.105.0), inside today's Conductor journey.
The producer holds intent and consequential approvals; a bounded composer writes
the execution score; Conductor assigns, integrates and assesses; players execute
complete spec slices. Preserve the already-uncommitted interactive-orientation
follow-up. The restoration is behavioral, not a wholesale rollback.

This is the execution score requested by the controller. Writing it authorizes
no implementation, release, installation, dispatch or lifecycle operation by
its composer. The controller executes subsequent steps only under the actual
user/session authority. Existing authorization is reused, not asked for again.
An execution score does not itself grant permission. Release and future-build
observations below have their own explicit applicability boundaries.

Preserve these safeguards throughout every step:

- Host permissions; actual operation authority; exclusions; planning-only stops;
  agreement before material outcome, quality, experience or scope changes.
- Ordinary Switch In's generic Conductor offer and direction-setting meaning;
  restored wider active work; unresolved human evidence; no contributor launch
  merely to choose an unauthorized task; no repeated workflow-entry approval.
- Current native Agent/Codex/Claude routes and established-partner selection;
  no fabricated access, silent provider substitution or new pairing.
- Distinct requested, reported, configured, host-declared, observed and unknown
  model/effort facts. A successful return does not establish either runtime value.
- Managed Conductor's existing exclusive owner, Codex-only pressure-aware
  coordinator/implementer, review gates, immutable agreement and supported JSON
  actions. No new driver action, nested dispatch, lifecycle or schema change.
- Actual evidence before claims; returned is not checked; passing commands are
  necessary but not sufficient; no invented measurements, results or approvals.
- No worker quota, arbitrary tier default, universal cheap-model rule or claim
  that dispatch counts demonstrate efficiency. No restored legacy mode markers,

## Step 1 — Restore composition, specification and assignment ownership

**What.** In the main skill and orchestration reference, replace the current
optional-composer-only account with the following contract. Keep detailed rules

   priorities and consequential agreement. Composer owns score content and score
   repairs. Conductor owns task-based session advice, staffing, dispatch,

   and evidence for individual complete steps. A composer call neither approves
   work nor becomes its persistent controller or independent reviewer.
2. For a non-trivial execution spec with useful bounded player work, call an
   available top reasoning-capability composer at a separately sized effort.

   reason and controller authorship before using the fallback score; assess it
   against the same success bar. Do not assert that it is necessarily inferior,
   silently substitute a named partner, or demand a new approval for an unchanged
   authorized task. Stop only if a real missing capability/decision prevents
   safe progress. Return later score defects for composer repair when available.

   non-code work with its appropriate artifacts and checks. A player must not
   re-derive product intent. Composer writes the substantive detail rather than
   delegating unfinished specification to a lower-capability writer.

   inspect remaining judgment, context transfer, access, tools, consequences and

   explicit independent/seam review for damage commands could miss. Mostly
   delegate is a bias for a well-factored multi-step score, never a ratio, quota,
   fixed number of keeps or allegation that every kept step is wrongly tagged.
6. Size the controller for dispatch, conformance judgment and escalation, separate
