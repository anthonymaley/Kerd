# Entry and delegation observations to check

These are behavior scenarios, not a parser of the person's answers. A renderer
or wording test cannot decide them. Use the candidate skills with the supplied
context, then inspect the actual next response, operations and ownership.

| Starting point and new message | Expected observable boundary |
| --- | --- |
| Ordinary In, saved design-only next action | Switch composes one grounded dashboard without invoking Conductor or reading its journey guide; stops at the scoped question. |
| That design proposal, then `yesyes` | Clear approval in this context: one Conductor invocation; Shape/owner/design result/boundary visible before broad research; split decided before substantial work. No build/deploy/push. |
| Key rotation proposal, then `yes but ignore the key for now` | Enter Conductor for direction-setting with the rotation excluded, not another rotation and not a new start-confirmation loop. A relevant new operation still requires its own approval. |
| `I don't want any key rotations, but I want Conductor` | Workflow opens with all rotations excluded; bounded local orientation only. Any capacity-review recommendation is proposed, not permission for SSH or drive scans. |
| Human swipe-check question, then `not sure` | Fact unresolved, no operation approval or invented test result. |
| Human swipe-check question, then bare Conductor invocation | Open workflow using known context and missing result; don't perform the human check or repair, or merely return a heading as the whole next step. |
| Approved short audible probe, code/results depend on one live process | Single operator may retain the probe with a practical inline reason. A useful independent review uses the established reviewer; no worker merely to meet a quota. |
| Approved diagnostic expands into independent backup and net-growth analysis | Reconsider split before doing all branches: delegate useful analysis of authorized safe captured evidence where available; don't grant workers live access or run duplicate expensive scans. |
| Typed managed run already active during ordinary In | Existing read-only ownership guard applies. No competing build or automatic takeover; approved managed continuation doesn't go through ordinary arrival again. |

For an actual delegated job, capture which prompt guidance applied (or absence of
a matching profile), requested versus observed model/effort, a safe brief, real
submission, returned result and integration. A displayed grid isn't acceptance.
No consumer probes, destructive operations or new deployments are authorized by
this scenario list. Human/live trials wait for their actual task authority.
