Switch fidelity — the handoff records exactly where we are, and nothing agreed is lost

Drawn from the repo at 9243b98 · 7 August 2026, 11:24 · read-only — this page changes nothing

Why this exists

When context window is filling, we can switch out to record EXACTLY where we are against the agreed stage/ladder/plan to allow us to clear the context window and start as if it was the same exact session and no memory or agreed points or input had been forgotten or lost. Whatever we need to make that happen we should do. If we can do that in a super efficient way even better (efficient means faster to switch in/out and fewest tokens required to do those steps) but NEVER at the expense of memory or context quality.
Straight from the frame — this is the requirement in the words it was given in, not a retelling.

What winning looks like

2 observed → 0
Course-correction interventions per pickup
no → yes
Ladder position available at pickup
unmeasured → 0, and measurable
Agreed points lost across a boundary
unbounded → bounded and complete
Read-set determinism

Risks

handled killer
Pruning to fix accretion introduces erosion — a short session's close overwrites CONTEXT.md and drops an agreed point recorded by an earlier, deeper session
What we do about it: pruning is licensed only at defined events — a goal record landing (docs/gates/*-goal.md) or an explicit agreed drop; CONTEXT.md is append-only between them, so a short session structurally cannot prune (Tony 2026-08-07)
Revisit when: the first prune that removes something a later session needed re-argues this row
watching
Reading more at pickup fills the window faster, forcing more boundaries — each boundary is itself a fidelity risk
What we do about it: — none —
Revisit when: design rung — a design that increases the read set without a compensating reduction re-argues this row
watching
The fidelity property stays unfalsifiable — no check exists that a pickup restored what the close recorded, so every countermeasure here ships unverified
What we do about it: — none —
Revisit when: design rung — this must be answered before the build rung, or the goal gate has nothing to measure
watching
"Read in full" instructions get silently bounded by the reader when the target is large
What we do about it: — none —
Revisit when: design rung — bound the read set explicitly, or restructure logs so the bound is structural
