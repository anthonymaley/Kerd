The property: **every gate on the rung must block from outside the model; advisory output is not a check** (absorbs "Refuse bad work"; CI is its first instance).
- **No solution vocabulary during the requirements walk** (2026-08-03, Tony's correction). Candidate views and interviews name requirements and outcomes, never skills — "we should not be thinking solution (skills) at this point". The Bree dogfood item is removed from TODO entirely (not blocked — gone).
- **Choose what matters next: two constant axes, both OUTCOME — consequence x value** (2026-08-03). Consequence is what it costs us not to do it; value is what we gain. **Effort is not an axis** — an input measure beside outcome measures makes the grid incoherent and flatters cheap work; it survives as a tiebreaker and as a slicing factor. Tested rather than argued: on the real backlog, "repin three repos" rose under effort as a cheap win and fell correctly under value to pure hygiene; the SPIKE rose for the mirror reason. Each item names **what we lose by not choosing it** (v0.68's rule applied to work). Blocked items are separated, not ranked. **The failure was never bad ranking** — it is items with no comparable form: no diagram, no structure, no ask. "Too much noise" does not mean volume.
- **A release is a GROUPING, not a time axis** (2026-08-03, corrects 08-02). Time may be attached later, or never. Five factors decide it, working three ways: **dependency** forbids (hard constraint), **user comprehension** caps (a release can be too big even when everything in it is finished — the bound comes from the receiving side), and effort/risk/opportunity shape. **The DONE condition is ASSEMBLED, never authored** — every item a conformance check against an upstream declaration. Nothing may be in DONE that nothing declared: it cannot be checked, so it passes by assertion.
- **A risk without a countermeasure is a BLOCKER** (2026-08-03). Flips the default so silence stops work instead of passing it. Risks are not unnamed — they are unmitigated, **unqualified** (the dangerous one: a named, unsized risk reads as managed) or accepted unknowns. **Evidence qualifies a risk, and it is a test OR an analysis.** Qualified = proven AND measured: impact in the value's units, likelihood recorded **separately** — never multiplied, because expected value is the wrong maths for a bet taken once. **Fatal = impact >= declared value, at any likelihood**; likelihood sets the response, not the class. Countermeasures are permanent or TEMPORARY (carrying a return condition; an unmarked temporary one is permanent by neglect). **The limit on acceptance: high impact + high likelihood + no countermeasure = dead project** — the one blocker that cannot be accepted by name.
- **"What we ruled out, and why" is its own artifact** (2026-08-03). Four functions independently demanded it. A rejected approach and a failed fix are the **same thing** — an option eliminated, one by analysis and one by a test. The unit is the **concept**, not the attempt and not the code; concepts outlive codebases. Filter: was it ever a candidate? A slip is not an option. **Read in GROUNDING** by everything that proposes, which makes it an input rather than a graveyard and partly answers reachability. **Capture must be a byproduct** — a failed verify IS the record; run through the risk machinery, a discipline-dependent log is high impact + high likelihood + no countermeasure = dead.
- **Hold product truth: CUT** (2026-08-03). It failed its own test — no question has ever needed answering that the code could not answer. The one measured failure behind it was **retrieval, not absence**: the doc existed. Retrieval relocated to the `reachable` clause; intent and value are already written by Frame the intent. **Return condition: a question arises that the code cannot answer.** Kept on the board struck through, not deleted.
- **A requirement row has four fields, in execution order: in / grounding / out / acceptance** (2026-08-03). Surfaced by Tony asking why evidence sat after outputs — it did not; one word was carrying three ideas. **Grounding** is what must be read before anything is produced, and it is the entry gate's real job: inputs arrive on their own, grounding is what gets skipped. **Acceptance** is what proves this run's output is good. The old `ACHIEVED:/GAP:` line was neither — it says whether the function *runs at all* — so it moved to movement 11, the first concrete instance of *Show where we are*.
- **Date records of events. Never date living documents** (2026-08-03). Test: *would rewriting this tomorrow be correct, or falsifying the record?* Correct → living, no date, git history is the archive. Falsifying → a record, dated, never rewritten. Second caller for the split switch already runs (CONTEXT.md overwritten / `kivna/sessions/` immutable). Homes: `docs/product/<slug>.md` + `.excalidraw` (living, same slug so the pair is derivable), `docs/gates/<date>-<slug>-<rung>.md` (immutable), vault (human-read, never duplicating git). Front matter carries `route` and stage so route-specific acceptance is machine-checkable. **Still open: *reachable*** — naming solves findability, not reachability; the 6 Jul design doc that held 1 Aug's answer was perfectly well named. **Not applied retroactively**: all 30 files in `docs/plans/` use the dated shape, including living ones; renaming is a rip and waits for approval.
- **Colour grammar: red = cost, green = Tony's input, blue = changed since last reviewed** (2026-08-03). Blue rather than red for deltas because red is load-bearing, and because everything is new once — red would creep across the board and stop signalling cost at all. Red and green outrank blue on collision (permanent meanings beat temporary ones) and suppressed deltas are reported, not dropped. Blue's baseline is an explicit `mark_reviewed`, never a commit or a regeneration — both move far more often than Tony reads.
- **Annotations are a queue, not an archive** (2026-08-03). Read → act → delete, disposition appended to `docs/plans/annotations/log.md`. This also dissolved the drift defect rather than mitigating it: preserved annotations kept absolute position but not attachment, so a comment slid away from what it annotated on reflow. A comment that lives one cycle cannot drift, so the anchoring machinery was never needed.
- **A tool declares the route it serves and is invoked on match** (2026-08-03) — not because it exists, and never as an obligation. Sensei's route: asserting a position, proving a gap or an idea with measurement, or a complex problem needing point of cause and 5 whys; **trigger: a problem that survived a few attempts to fix it**, which is a condition a machine can detect. Same rule for superpowers and every external tool. Sensei is **proven elsewhere** (`~/toyota-sensei` and other projects) and never run inside Kerd — so the bet is *transfer*, not the method.
- **Kerd's gap is above the contract rung, and it is a routing problem as much as a capability one** (2026-08-02/03). Measured, not argued. Four altitudes: **product** (empty) → **design** (superpowers specs, alive but never retrieved) → **contract** (conductor's spec file, won it in July) → **implementation** (superpowers plans: 10,177 lines, **0 of 472 checkboxes ticked**, superseded). Usage: switch 20×/day and skriv daily; kivna and conductor implicit; tend and trim occasional; **mode, sherpa, interrogate and capturerequirements never used at all**. Cause is reachability — the cross-skill reference graph shows **sherpa is an orphan** and conductor's only routes are kivna/slainte/switch, all lateral or downstream. Superpowers wins not on merit but because `using-superpowers` injects "you MUST use this before any creative work" at session start; sherpa waits to be named. **Release is not a fifth rung — it is the time axis**, and each release cuts through all four.
- **Don't adopt OpenSpec, Spec Kit or BMAD; don't clone superpowers; don't remove it either** (2026-08-02). Its two halves had opposite fates — the design specs earned their place and are still referenced; `writing-plans` was already superseded by conductor in July (superpowers artifacts: 20 Jun / 17 Jul / **0 Aug**). Adding another framework would make the measured artifact-scatter worse (`docs/plans/`, `docs/superpowers/`, `docs/requirements/`). Borrow three things instead: a **fresh-context reviewer**, **test bias by layer**, and **contract tests**. Codex's own cited benchmark argues against loading generic methodology, then recommends four frameworks — the citation undermines the advice.
- **Nothing in the system can refuse, and nothing counts** (2026-08-02). **0 CI workflows and 0 pre-commit hooks across every repo.** Every gate in Kerd is prompt-layer — a model choosing to comply. This is the only item that changes what is *possible* rather than what is *likely*, and it is the least Kerd-shaped thing on the list. `/loop` **MUST NOT** run where nothing can refuse.
- **Design is agreed in diagrams, not prose** (2026-08-02, re-confirmed by running it 08-03). Tony thinks in high-level diagrams; prose is the wrong review modality, which is what "too much noise" has meant every time. The grammar comes from his DDIL deck: numbered movements, a **constant verdict line per option on two fixed axes**, **colour marking cost**, **named bets discharged by name**, **containment rather than arrows**, and an **altitude shift** between movements. Mermaid cannot express this. Sensei's A3 story types supply the narrative structure (compare/contrast is *current → new → what changes*, which is v0.68's rule arrived at independently). **Arrows are the one exception, used in stage flows only** — sequence is the point of a flow and containment cannot express order. Evidence for the whole decision: every substantive correction on 2026-08-03 came from drawing it, not discussing it — the question-exit, the true width of the triage branch, and the two-document split were all invisible in prose.
- **Conductor commits its own work; switch keeps the boundary** (2026-08-02, v0.67.0). Two kinds of commit, two owners: *work commits* (code + travelling docs) are conductor's, pushed as each task's verification gate passes, staged by name; the *session-state commit* is switch's, once, at the boundary. Pull stays switch-only. This resolved a real contradiction — conductor's principles banned pull/push in one line and pull/push/commit in the next, while "docs travel with code, in the same commit" required a commit that could never happen. Rationale beyond convenience: v0.66's collateral check only works on a small diff.
- **Say it in the user's terms** (2026-08-02, v0.68.0). Sibling of v0.65's gate rule: that fixed findings that were *missing*, this fixes findings that are *present and unreadable*. Any change altering what the user can do is stated as **now / the change / what it means**, in the vocabulary of using the thing; a removed capability must be **named as a loss** or it disappears into the good news. Question test: *could they answer it without reading the code?* If not, it is your call, not theirs.
- **Conductor re-seated: four roles, orchestrator is a call not a mode** (2026-08-01, v0.66.0). Tony's observation: conductor works well with Fable driving, but too many Fable tokens go to *managing* subagents. First framing (a "sub-conductor" under Fable) was replaced by his own inversion, then corrected once more to the seating that leaves no authority overlapping: **composer** (Tony — intent) → **orchestrator** (top-tier model, called as a subagent, writes the score, leaves) → **conductor** (the session model — dispatch, verification, escalation) → **players** (sized cheap subagents). The dominant saving is *context size*, not task allocation: the orchestrator holds one brief instead of a whole accumulating session. Consequences: the model advisory now recommends the *conductor* model and never the top tier for difficulty alone; the orchestrator is called in two passes (scope → score) and **writes the spec to disk, returning only a summary**; tags are assigned *after* the step body is written; blast radius is answered by a `[keep]` review step, not by keeping the risky edit; and the conductor **may re-dispatch, never re-specify** — three failures hands the passage back. Rejected: splitting orchestration from transcription (a "copyist" tier) — spec detail is where judgment is encoded, and it's the safety mechanism, not padding. Also rejected: a third tag naming *why* a step is kept — tags encode actions, reasons go in the step body. Evidence that shaped it: dinner-tonight's live spec (50/50 keep/delegate, both keeps fully specified — tags recorded how hard steps *felt* to plan) and a 3of3 quote ("my deletion range swallowed three helpers") which reversed the blast-radius claim mid-draft.
- **The gate message carries the content — findings are not framing** (2026-07-19, v0.65.0): a conductor session in `~/3of3` showed near-zero communication — analysis done, then straight to "execute the plan?". Root cause was a three-way interaction, not a single bad file: (1) Claude Code's native focus mode shows the user only a turn's *final* text message, so analysis written between tool calls is invisible; (2) the global CLAUDE.md question-formation gate ("don't bury the question under framing") got read as license to strip the findings from that final message; (3) conductor's approval gates make a question the turn's last beat. Fix shipped in both layers: conductor now requires every gate message to contain what's being approved (plan-phase rule + principle), and the global gate got a "findings are not framing" clarification — lead with the deliverable, end with the one ask. Ruled out: 3of3's CLAUDE.md (doc rules only), its Kerd hooks (0.63.0, alive in cache), and the partner-mode hook (not firing there — 3of3 still has pre-rename `kivna/.focus`, and the hook reads `.pair`).
- **Conductor: model advisory replaces the `fable` toggle** (2026-07-11, v0.64.0): the `/kerd:conductor fable on|off` toggle is **removed**. A skill can't read or set its own model, so conductor doesn't detect or assert it — right after orient it sizes the task, **advises the driving model** the work needs (mechanical → current model fine; hard/architectural/judgment-heavy → top-tier Opus/Fable), and **gates**: user switches to it or confirms before planning. Delegation is then conductor's default right-sizing, not an opt-in: if the task has mechanical bulk it writes a spec file; steps are tagged `[keep]` (driving model does inline; was `[fable]`) or `[delegate]`, and each `[delegate]` step carries a **sized model + effort in the tag** (`[delegate, model: haiku, effort: low]` … `[delegate, model: sonnet, effort: high]`) approved at the plan gate. Small/all-judgment tasks skip the spec and run lean inline. Supersedes the v0.62.0 explicit-toggle decision and the v0.63.0 effort-hint (effort now lives in the sized tag alongside model). **The spec is the contract** stays — a vague `[delegate]` step yields a confidently-wrong build; spec quality is the safety mechanism. Provenance of the tiering idea: a friend's Fable workflow; its compact/checkpoint ideas were **rejected** — switch owns boundaries, conductor never manages context or compacts.
- **Switch-in Summarize ends with a numbered pick-list** (2026-07-06): the full `## Now` + `## Backlog`, one terse line each, so the user picks by number or steers. No truncation (TODO is lean by design), no reply-hint.
- **State/work/history are different things — one file each** (2026-07-03). Completeness comes from full-fidelity session logs + git history of CONTEXT.md (pruned content is never lost); efficiency comes from reading less, not storing less. The sharp edge: CONTEXT.md must never become a diary — the session log is the diary.
- **Closure inference is a readable list, never a prompt** (2026-07-03): switch-out shows done/open/unsure verdicts; a "done" verdict requires session evidence (commit, file, log entry); only unsure items become a question, asked once at next switch-in.
- **kivna save writes without approval** (2026-07-03): switch-out is the single vault write path, so an approval gate was pure friction; do-not-save markers remain the privacy control. Scaffold keeps its approvals (it creates from an interview; save just reflects the session).
- **Conductor's decisions live in CONTEXT.md, its plan in TODO `## Now`** (2026-07-03) — settled the design doc's open contract question; no separate conductor line needed.
- **Vault Status.md: written at switch-out, never read at switch-in.** The vault stays human-first; it contains nothing the log + CONTEXT.md don't. (This also answers the old vault-spec question about the cold-LLM-read consumer: the LLM reads CONTEXT.md, the human reads the vault.)
- **Older session logs are archive, never per-session load.** Safe because forward-only discipline carries live items and the playbook is the durable gotcha net — switch-out verifies gotcha mirroring before commit (hardening after Test 1 found a five-day-old unmirrored gotcha).
- **conductor (session) + sherpa (lifecycle), split by timespan** — sherpa guides the multi-session climb, conductor keeps one session in tempo. "coach" rejected (too sporty); "sensei" rejected (collides with the sensei plugin, oversells).
- **A mode is a right-sizing contract, not an orchestration checklist**; skills are everyday tools. Kerd owns its modes — not a router over external skills (GSD removed v0.43.0; Superpowers distrusted as waterfall).
- **sherpa = one skill; Kerd stays one plugin.** Durable state in committed `kivna/sherpa.md` (one repo = one idea); `.active-modes` holds only a session pointer (session-ephemeral).
- **Validate is risk-driven, not menu-driven** — find the killer assumption, run the cheapest test of it, clear only the fatal risks. Design: `docs/plans/2026-06-29-validate-methods-toolkit.md`.
- **jit + spike stay standalone modes** (Tony needs jit for the dogfood); folding/retiring the rest of the prune list is deferred until the dogfood teaches us what the stages need.
- **Memory tools (claude-mem/mem0/mempalace/beads/agentmemory): adopt none** — they break git-portable handoff and human-first, and solve a retrieval problem Kerd doesn't have.
- **skriv voice profile: HELD** — don't wire until non-founder-genre samples exist (n=1: profile at `~/eolas/vault/people/Anthony Maley Voice.md`).
