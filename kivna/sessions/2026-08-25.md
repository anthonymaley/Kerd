## Gotchas

- **A cached image read silently defeats the only check a diagram has.** The
  standing rule is that nothing checks a rendered diagram but a person opening
  the PNG. Re-reading a PNG immediately after re-rendering it returned the
  *previous* image, showing an overflow that had already been fixed — and would
  equally have hidden one that had not. The byte count was identical, which made
  it look correct. Re-read only after confirming the file actually changed, and
  treat an unchanged size on a changed source as a cache hit rather than a no-op.
- **`view_fingerprint` takes file CONTENT, not a path.** Passing paths produced
  two plausible twelve-hex fingerprints that were silently wrong. Caught only
  because the gate refused with a mismatch — nothing about the values themselves
  looked off.
- **`## Grounding` accepts phantom symbols.** AU5 resolves file *paths* against
  the filesystem and never checks symbols named inside a line, so a grounding
  entry citing a function `stage_ahead` that does not exist in `kit.py` passed
  clean. The section certifies that files exist, never that what you said about
  them is true.
- **A `cd` into a subdirectory leaked into a later Bash call and a headless-Chrome
  screenshot landed in the repo root.** Already a known gotcha; this is a
  confirming instance, and the symptom was an untracked stray PNG at switch-out.

  transferable part.** Asked *"do these say what you mean?"* the review found
  nothing. Asked *"are the descriptions and text correct on the diagram?"* the
  same drawing yielded four factual errors in ten minutes. **Agreement and
  correctness are different reviews, and only one of them was being run.**
- **A drawing was refused five times across three sittings, and the same panel
  broke four of those times.** `slice → scope` overclaimed the rename as free,
  then named the wrong section, then missed the gate move, then miscounted. A
  claim that keeps being wrong in the same place is not bad luck — that panel is
  where the item's real complexity lives, and its repeated failure was a better
  signal than any single fix.
- **The most dangerous defect this session found would have left everything
  green.** New closure records are `-acceptance.md`, and conductor, slainte and
  switch all trigger completion behaviour on `*-goal.md` landing. The rename
  would have left every artifact, gate record and drawing correct while silently
  disconnecting the behaviour they describe. Nothing on the board would have gone
  red. The producer's rule — *aliases read old records, they never fire new
  lifecycle events* — is aimed exactly there.
- **Calling a model to refute the session's own instinct paid twice.** Once by
  killing the risk-to-viability move on fetched evidence, and once by finding two
  real errors in the design package it was handed — including a count of five
  asserted behind a list of four, with the shortfall hidden in the phrase *"and
  one more"*. **The brief that produced that was the one telling it to report
  anything wrong rather than paper over it.**
- **A count asserted ahead of its evidence reached an immutable gate record.**
  Not a typo — a number written before the list supporting it existed, with the
  gap absorbed by vague language. It is the same class as the four phantom
  dependencies of 2026-08-14, and the phantom `stage_ahead` function is the same
  class again. Two instances in one document suggests the failure mode is
  specificity-without-verification, not carelessness.
- **`enters_at` was read backwards in a design doc.** It names the deepest
  *passing* rung, not the next rung to do — so a claim about which items would
  "regress" got both the direction and the current state wrong. Worth noting
  because the field is read constantly and the misreading was invisible until
  something checked it against the tree.
