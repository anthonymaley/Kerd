## Gotchas

- **Renaming a thing whose docs talk *about* the rename corrupts under blind find-replace.** Several files said "the dian skill, to be renamed conductor" / "rename dian→conductor"; a global swap produced "conductor→conductor" nonsense. Fix: split references into **plain** (safe to bulk-replace) vs **meta** (text about the rename — hand-edit), and split docs into **living** (rename) vs **historical** (leave as the record — release notes, changelogs, session logs). Also: macOS/BSD `sed` lacks `\b`; use `perl -pe` for word-boundary swaps. The `.active-modes` line contract (skill writes it, hook greps it, test asserts it, switch reads it) must move in one commit or the hook/test harness breaks quietly — the test harness was the safety net that confirmed it held.

## Insights

- **The right framing question dissolves the hard part.** Validate looked like "the hardest, least-specified stage" until "risk-driven, not menu-driven" collapsed an open-ended methods-toolkit into a tractable shape. Same move as last session's "ask what a mode FAILS to do." Leverage is in the framing question, not the enumeration.
- **The name fell out of the role's timespan, not a thesaurus.** sherpa vs coach vs sensei resolved once the question became *how long does this job last?* — one session (conductor) vs a months-long expedition (sherpa).
- **Locking decisions exposes the next hole.** Writing "stage tracking in `.active-modes`" forced "but that file gets cleared" — the act of recording the decision found the Phase 1 blocker. Cheap to surface early, expensive to hit mid-build.
- **Shipping in slices kept a 6-ship session honest.** Each stage was an eyeball-gated slice with its own release + reconciled records (TODO/Status/Weekly), so the repo was never half-true between ships.
