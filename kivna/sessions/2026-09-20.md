## What shipped

**0.142.1: anyone can install it.** Kerd's marketplace manifest declared the plugin's
source as `git@github.com:anthonymaley/Kerd.git`, an SSH address. `claude plugin
marketplace add` survives that, because the CLI's `github` shorthand probes SSH and falls
back to HTTPS. `claude plugin install` does not: it clones the declared address literally.
So the second of the two commands printed on the front page failed for anyone who had not
set up a GitHub key, leaving no plugin and none of the eight skills. The source is now
`https://github.com/anthonymaley/Kerd.git`. CI green; the published fix was then proved by
a keyless install against the live marketplace.

## How the sitting turned

Shape sent out two read-only jobs before touching anything: could a stranger reach the
marketplace at all, and could an install run without touching Anthony's own profile. Both
returned and both had their central claim re-checked rather than accepted. The first found
the SSH source; its transport half was reproduced directly, `Permission denied (publickey)`
with no key against the same repository that answers anonymously over HTTPS. The second
found `CLAUDE_CONFIG_DIR` and proposed a before/after integrity check — which was wrong,
and replaced: comparing file checksums cries wolf, because ordinary marketplace
auto-update rewrites `known_marketplaces.json` on any `claude` invocation. The replacement
compares structure and ignores timestamps.

With Anthony's go the commands ran in throwaway profiles, once with a key and once with
SSH refused by a PATH shim. With a key: 0.142.0, eight skills, none of the four retired
ones. Without: refused, nothing installed.

**The obvious fix was wrong, and only the run caught it.** Naming the project as GitHub
shorthand — the way the working first command names it — was applied and still failed
identically. The `github` source prefers SSH on the *install* path and only falls back when
`CLAUDE_CODE_PLUGIN_PREFER_HTTPS` is set, which no newcomer sets; setting it made the same
install succeed, which is how the mechanism was established. Only an explicit public
address works unaided.

Anthony chose to ship it as 0.142.1 with a release note rather than quietly repairing what
0.142.0 points at, then approved the push after Codex cleared it.

## Review

Codex (`codex-tui`), read-only, twice. Its first verdict was **not clear to push**, on two
overstatements in the release note, and it was right about both. The important one: the
note said the SSH address was "private" and that only the author could follow the
instructions. The repository is public and an SSH clone of a public repository succeeds for
anyone with a GitHub key registered — so the door was shut to people without a key, not to
everyone but the owner. Both were corrected, in the release note, the work record and the
diagram, which repeated the same error in its headings. Its second read: clear to push. It
ran no install and no tests, and said so.
