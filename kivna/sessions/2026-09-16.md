## The finding worth carrying

**The defect was never one sentence. It was a class of sentence.** Seven were found
across three files, each reading like discipline while handing the model an
unfalsifiable judgment about its own work:

> "only if it clarifies a real relationship" · "whenever they help understanding" ·
> "when it helps" · "when spatial detail warrants it" · "a substantial proposal" ·
> "Optional job/diagram tools" · "a small inline relationship can be enough"

That last one survived in `skills/visuals/SKILL.md` — the skill whose entire job is
rendering views — after being removed from `journey.md`, because the brief that produced
the fix named sections instead of asking for a sweep. Codex found it. Static gates were
green the whole time all seven were live.

The repair that mattered was making the threshold **countable**: two or more connected
parts, a branch, an ownership boundary, or a before → after change. "Substantial" carries
no test a model can fail; a model can call a multi-part proposal small because it is easy
to *describe*.

## Evidence discipline — the part that should survive

Behavioural claims went wrong twice before going right.

1. **No control arm.** The first design would have made a pass meaningless: if a
   treatment worker draws, that could be the rule, the model's disposition, or
   `diagram-design` sitting in its tool list.
2. **Read too early.** The second was scored off disk while workers were still running,
   producing a reported *failure that did not exist* — a recommendation not to ship,
   built on a snapshot. Both "phantom" runs finished at 26 and 37 minutes having produced
   their files all along. Corrected in the work record rather than buried.
3. **Three arms, pre-registered.** The third isolated each rule separately, used
   byte-identical prompts, and fixed the scoring criteria in writing *before* the last
   runs reported — including the note that the scorer is the party who wants the release
   to pass, and that borderline runs score PARTIAL.

Results: visual rule marginal **3/3 vs base 0/3**, no over-fire **0/3**, outside
Conductor **2/2**, explicit request **2/2**. Capsule rule **4/4 vs 0/4** after tightening,
up from 1/3. Nineteen valid runs plus an eight-run re-test; one pilot recorded INVALID.

The capsule tightening is the clearest example of the method working: the five partial
failures failed *identically* — models gave the recommendation early, then asked, leaving
the block above the bubble carrying only the deciding consideration. The word "minimum"
had read as licence to omit what was already said. Telling them to **restate** it moved
the result from 1/3 to 4/4.

## The refusal that shaped the release

Claude proposed a `PreToolUse` hook that would deny a `kerd:effort-*` dispatch with no
explicit `model`. **Anthony refused it: "It turns a missing tool argument into a hook
subsystem."** He set the contract instead — `model` in the call, `subagent_type` for

Worth keeping: the proposal had already found two real defects in its own design (the
`hooks.json` nesting trap, the four-alias tool enum) and would have shipped a subsystem
whose tests could pass by doing nothing. Being right about the details of a
disproportionate mechanism is not an argument for building it.

## The finding: 0.132.0's defect class, produced three times while removing it

Four review passes — one Opus job at high effort, then Codex `codex-tui` across three
before-push rounds (five findings, then three, then clean).

**Every defect found was a calibration defect. Not one touched the design.** And three
of them were the *same* error: a rule stated so absolutely that a legitimate situation
could not satisfy it.

1. "Every `Agent` call names both keys — omitting either is a defect" contradicted the
   no-effort-agent route documented two paragraphs earlier.
2. The fix for that, which made both keys absolute, created the contradiction rather
   than resolving the asymmetry the Opus pass had flagged.
3. Adding the `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` fact without saying what to do when
   it fires — a rule unsatisfiable exactly when it binds.

A rule a model cannot satisfy is one it will exempt itself from, and the exemption it
invents is not the one you wanted. This is the mirror image of 0.132.0's seven
unfalsifiable sentences: that release removed rules a model could always pass, and
this one kept writing rules it could never pass.

## Overclaims removed, and two of Kerd's own facts corrected

The draft called its own prose "the guard" and said what ran "is verified". Neither was
true. The honest limit was already written in the work record and had not reached the
guidance.

Checked against the subagent docs rather than argued from memory:

- The resolution order is per-invocation `model` → definition frontmatter →
  `CLAUDE_CODE_SUBAGENT_MODEL` → the caller's model. "Silently inherits the caller's"
  was one branch of two, asserted in eight places **and pinned by a new CI assertion**,
  which would have refused its own correction.
- The `model` field accepts full IDs as well as the four aliases; the enum is this
  host's *tool parameter*.
- A per-invocation `model` persists into a `SendMessage` resume, so the resume is an
  argument for naming it, not the coverage gap the notes claimed.
- `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` makes the host ignore the field entirely, and an
  `availableModels` allowlist can substitute another model. So the call *requests*.
