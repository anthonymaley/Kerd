## Gotchas

- **An incomplete switch-out reads as a clean tree but isn't.** The 2026-06-10 work was done but never committed; `git status` said "up to date with origin" because nothing was staged. The tell was the session log's `## Commits: (hash pending)`. Switch-in should treat a populated working tree with no matching commit as an aborted handoff, not a clean pickup.
- **The running switch skill was the cached 0.39.0 copy while the repo was at 0.41.0.** The plugin cache lags the repo. When dog-fooding a just-shipped skill change, follow the repo's current behavior, not the loaded (stale) skill text — otherwise you re-introduce the bug you just fixed.
- **"Formalizes existing behaviour" was false.** The spine doc claimed `sessions-of-record/` was the standard "written by switch"; a ground-truth check showed only 1 of 5 cited projects had it, and switch writes to repo-side `kivna/sessions/`. Always check a "this is the status quo" claim against disk before building on it.
