## Gotchas

- **A green run on a fixed tree proves nothing about a guard.** After building
  the stage-schema check, running it returned clean — which it would have done
  whether or not it worked. The check only became evidence after reproducing the
  actual regression (renaming a heading back) and confirming it exits 1 naming
  both halves. Build the guard, then break the thing on purpose.
- **`grep -v "^[+-][+-]"` silently swallows real diff lines.** Filtering a diff
  to drop `---`/`+++` also drops any content line starting with two of those
  characters — a markdown bullet `- **text**` becomes `-- **text**` in a diff
  and vanishes. A diff that looks empty after filtering is not an empty diff.
- **`$?` after a pipe is the LAST command's exit code, not the interesting
  one.** `python3 gen.py | tail -5; echo $?` reports `tail`'s success while the
  script crashed. Check the exit code before piping, or use `PIPESTATUS`.
- **A regex with `.*?` and `re.S` crosses element boundaries in HTML.**
  Extracting stage headings from a rendered page paired the wrong heading with
  the wrong blurb and dropped one entirely, which read exactly like a page
  defect. Scope the pattern to the container element before believing the output.
- **Running a generator to inspect its output rewrites committed files.**
  `gen_project_types.py` calls `mark_deltas`, which re-marks blue "changed since
  reviewed" state; `progress.py` bare writes the committed trio. Both are
  correct behaviour and both dirty the tree — use `selftest`/`check`
  subcommands for inspection.

## Key Decisions

**Machine-local state is a real category and it had no inventory until now.**
The move lost exactly the things git cannot carry — the pair toggle, the
conductor marker, `~/.claude/settings.json` — and gained one thing git cannot
see: hand-wired hook drift in the user-global config. `docs/machine-setup.md`

**An SSH key does not authenticate `gh`, and the failure is silent in the
direction that matters.** `git push` works, so the machine reads as configured;
the API client is separately unauthenticated and only a call that hits the API
reveals it. This is why the setup doc verifies `gh` with `gh run list` rather
than `gh --version` — the same *check the runtime value, not the surface* rule
the 2026-08-25 f-string gotcha established, one layer out.

## Gotchas

- **A green `git pull` is not proof the remote is reachable.** On an
  already-current tree it returns `Already up to date.` from local state. On a
  fresh machine that reads as "git is configured" when the transport may be
  untested. `ssh -T git@github.com` is the real test.
- **An SSH key does not authenticate `gh`.** Different doors: the key signs git
  transport, `gh` is a REST/GraphQL client needing its own OAuth token. A
  machine can push and pull perfectly with `gh` holding no config at all.
- **`progress.py` has no `check` subcommand — it is `stale`.** The playbook said
  `check` and was wrong. Bare `progress.py` rewrites the committed trio, so
  `stale` is the only read-only form.

## Insights

- **The double-fire was reported as inferred and confirmed one turn later,
  and the honest tag is what made the confirmation legible.** It was stated as
  *configuration verified directly, double-injection inferred from that
  configuration, not observed firing*. The next prompt printed both injections
  above it. Had it been reported as "verified" up front, the actual evidence
  arriving would have been invisible — there would have been nothing to
  upgrade. The provisional tag is not hedging; it is what leaves room for
  evidence to land.

- **The most dangerous config drift on this machine was one that made things
  look MORE configured, not less.** A missing `.pair` file announces itself the
  first time partner mode does not fire. A *duplicate* hook fires correctly,
  looks like the feature working, and quietly injects instructions that
  contradict the live ones. Absence is loud; redundancy is silent. Everything
  in the move checklist that greps for something that must print *nothing* is
  aimed at this asymmetry.

- **The setup doc's shape was decided by the repo's own defect class rather
  than by convention.** A prose checklist would have been the obvious form and
  would have been another declared contract joined to reality by nothing.
  Pairing every requirement with its verify command is the same countermeasure
  as `check_stage_schema()` and AU10, applied to a document instead of to code.
