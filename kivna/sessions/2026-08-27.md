## Gotchas

- **A green run on a fixed tree proves nothing about a guard.** After building
  the stage-schema check, running it returned clean — which it would have done
  whether or not it worked. The check only became evidence after reproducing the
  actual regression (renaming a heading back) and confirming it exits 1 naming
  both halves. Build the guard, then break the thing on purpose.
- **`grep -v "^[+-][+-]"` silently swallows real diff lines.** Filtering a diff
  to drop `---`/`+++` also drops any content line starting with two of those
  characters — a markdown bullet `- **text**` becomes `-- **text**` in a diff
  and vanishes. A diff that looks empty after filtering is not an empty diff.
- **`$?` after a pipe is the LAST command's exit code, not the interesting
  one.** `python3 gen.py | tail -5; echo $?` reports `tail`'s success while the
  script crashed. Check the exit code before piping, or use `PIPESTATUS`.
- **A regex with `.*?` and `re.S` crosses element boundaries in HTML.**
  Extracting stage headings from a rendered page paired the wrong heading with
  the wrong blurb and dropped one entirely, which read exactly like a page
  defect. Scope the pattern to the container element before believing the output.
- **Running a generator to inspect its output rewrites committed files.**
  `gen_project_types.py` calls `mark_deltas`, which re-marks blue "changed since
  reviewed" state; `progress.py` bare writes the committed trio. Both are
  correct behaviour and both dirty the tree — use `selftest`/`check`
  subcommands for inspection.

## Insights

- **The cheapest defect-finding move all session was reading a draft, and the
  producer made it twice.** AU10 and the stage-to-suffix contract were both
  found by looking at the artifact about to be written and asking what the
  machine would do with it — not by reading code, running tests, or reviewing a
  diff. The draft is a specimen of the thing the system will accept, and
  inspecting it tests the acceptance path end-to-end in a way no unit fixture
  did.
- **The third gap was in code thirty minutes old, written by the same session
  that had just fixed the second.** That is not carelessness so much as
  evidence that fixing one instance of a class does not immunise you against the
  next: `legal_stage()` was the correct fix for "no front matter" and the wrong
  bar for "front matter that contradicts the filename". After closing a gap,
  ask what the NEW check still lets through.
- **A blind reviewer's wrong finding was as informative as its right ones.**
  Flagging conductor's "work handoff" as invented — when it is the producer's
  own ruling — exposed that `README.md:42` carries the non-compliant twin. The
  reviewer could not know the ruling, and that ignorance is exactly what made it
  read both sites as one inconsistency. Filtering blind findings costs less than
  the findings are worth, but the filtering is not optional.
- **Verifying before reporting saved three false alarms in one sitting** — a
  "missing" fingerprint that lives in the product doc by design, a "wrong" stage
  order that is deliberate focus-first rendering, and a "swallowed" conductor
  diff that was a broken grep. Each looked like a real defect and each would
  have cost the producer attention. The discipline is cheap; the alternative is
  a reviewer nobody trusts.
- **The pass that fires on completion found drift in the sentence explaining
  why drift happens.** The playbook's `## Current Status` says two homes for one
  fact is how drift happens — and its own example had gone stale. Nothing is
  exempt from the thing it describes.
