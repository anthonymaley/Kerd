## Key Decisions

- **Conductor advises the model, never detects or sets it.** A skill is a prompt injected into an already-running session — it cannot read or change its own driving model. So the design is advice + a confirmation gate ("switch to X or confirm you're on it"), not auto-detection. This is what replaced the earlier `fable on|off` explicit-assertion toggle — the toggle's job (assert you're on a strong model) is now a per-task advisory conductor raises itself.
- **Delegation sizing lives in the step tag, not at dispatch.** `[delegate, model: …, effort: …]` puts the model+effort choice in front of the user at the plan gate, so they approve the tiering, not just the steps. (v0.63 had effort as a dispatch-time hint; folding model+effort into the reviewable tag is the change.)
- **`pair` over `focus`, and over `brevity`.** Tony floated "brevity"; rejected — it names the terse output, not the partnership core (the skill's own description is "partner mode"). `pair` = pairing, rapid back-and-forth + check-in. English kept (Tony's call, not the Gaelic convention here).
- **Rename was surgical, not a sed sweep.** "focus"/"focused" as the plain English word ("current focus", "focus on pricing", mode headers) had to survive; only skill/hook/state/marker references changed. Historical changelog entries (v0.42/v0.62/v0.63) and session logs left as-is — they record what shipped then.

## Gotchas

- **Cache GC breaks pinned hook paths even in repos you never touched.** The wired cache path doesn't only go stale when *you* update the plugin — Claude Code garbage-collects old cache versions, so a repo pinned to `.../kerd/0.41.0/hooks/` breaks the moment `0.41.0` is pruned (cache kept `0.41.1`), erroring on every Stop. `~/3of3` sat broken this way with no local change. The Kerd dev repo is immune — its hooks point at the versionless repo path. Mirrored to `docs/playbook.md`.

## Insights

- **The model-advisory reframing is cleaner than the toggle it replaced.** The toggle carried an awkward premise — the user asserting "I'm on Fable" to a skill that couldn't verify it. Flipping it so conductor *advises* which model the work needs turns that same unverifiable-model constraint into a feature: the user was always going to be the one who knows/sets the model, so make conductor's job to *recommend* and *gate*, not to *know*.
- **Renaming a skill is genuinely cross-cutting and reaches outside the repo.** Beyond the obvious dir/file/test renames, `pair` touched: the global `~/.claude/settings.json` inline hook, the live per-repo state file, plugin descriptions (byte-identical constraint), and the `.active-modes`/marker vocabulary. A `grep -ril` up front (blast-radius scope) before editing was what kept it from being a whack-a-mole of missed references.
