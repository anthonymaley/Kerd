## Gotchas

- **On a tree with uncommitted work, `git checkout --` is not an undo — it is a
  different edit.** It restores from HEAD, not from the working tree. Bit twice
  in one session: a review subagent ran it against the live repo and reverted
  in-flight work (recovered only because the blob was still unreachable-but-present
  in the object store), and the expert-user harness used it to "restore" a
  drawing and silently reinstated a pre-amendment version, muddying two exercises.
- **A review subagent can escape a git worktree into the parent repo.**
  `gate.py`'s `_walk_up_for_git` tests `os.path.isdir(cur/".git")`, and in a
  worktree `.git` is a **file** — so the test is false and the walk continues
  past the boundary. Brief reviewers with "read-only" naming every mutating git
  verb explicitly; "do not fix anything" is heard as "do not edit files".
- **A closing check written after round N catches round N's defect class, not
  round N+1's.** The scan built to stop the enumerated-sweep failure was itself
  scoped to the eight files earlier findings happened to name — an enumeration
  wearing a script — and a live retracted claim sat outside it, one word of
  paraphrase (`has EXACTLY one implementation`) past a literal pattern.
- **Widening a vocabulary scan repo-wide produces mostly noise.** 99 hits, nearly
  all legitimate history: a doc saying *"amended at the goal gate, 2026-08-05"*
  is dating an event. The rule that survived: **claim patterns generalise (a
  false claim is false anywhere); vocabulary patterns do not.**
- **Preserving a struck claim verbatim trips any checker that hunts the claim.**
  The house pattern requires strike-in-place with the original intact;
  strikethrough is invisible to a regex. The R3 quoting problem, one layer down.
