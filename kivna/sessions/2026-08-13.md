The reported symptom (`Unknown command: /switch` in `~/work-anthony`) was a red
herring: skills are namespaced, so the invocation is `/kerd:switch`. The *real*
bug the investigation found is that **Kerd's hooks were dead across eleven
repos**. The old mechanism (tend pastes a version-pinned plugin-cache path into
each repo's `settings.local.json`) is the anti-pattern the plugin docs name:
Claude Code garbage-collects old cache versions, so every pinned path dies the
moment its version is pruned — `docs/playbook.md` already documented this exact
GC-pin-rot gotcha (2026-07-11).

Fixed by moving to the standard mechanism, shipped v0.96.0:

- **`hooks/hooks.json`** created (pair, session-start, skill-complete) — the
  harness auto-registers it on enable, and `${CLAUDE_PLUGIN_ROOT}` resolves at
  runtime, so no repo ever pins a cache path again. Verified from live docs via a
  claude-code-guide agent (code.claude.com): the var expands in a plugin's own
  hooks.json but NOT in user settings.local.json.
- **`hooks/stop.sh` cut**; `hooks/hooks.template.json` retired (superseded).
- **`skills/tend/SKILL.md`** Category 9 rewritten — migrate/remove stale manual

## Gotchas

- **`${CLAUDE_PLUGIN_ROOT}` expands in a plugin's own `hooks/hooks.json` but NOT
  in user `settings.local.json`** — the whole reason auto-load works where manual
  wiring needed absolute paths. Mirrored to the playbook (folded into the
  resolved GC-pin-rot gotcha).
- **AU5 grounding refs must resolve on disk** — a URL in a `## Grounding` line
  fails the audit ("does not resolve"). Put external-doc citations in prose/risk
  evidence, not as a grounding bullet.
- **A subagent told "STRICTLY READ-ONLY" still wrote `output/`** into the repo
  (StrictDoc's `_cache`, 2026-08-08) — it is still sitting untracked at root,
  left for boundary triage.

## Insights

- **The reported symptom was not the bug.** "Unknown command: /switch" pointed at
  the command namespace; the actual failure was dead hooks from cache-version
  pinning. Chasing the red herring would have "fixed" nothing. The dead-command
  string even turned out to be *emitted by the broken hook itself* (stop.sh's
  `/switch out`), closing the loop.
- **The fix supersedes a backlogged countermeasure.** The playbook's proposed
  fix for GC-pin-rot was an automated staleness check in tend. Auto-load removes
  the pinned path entirely — killing the bug class beats detecting-and-repairing
  it. The backlog row is now moot.
