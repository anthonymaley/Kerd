The reported symptom (`Unknown command: /switch` in `~/work-anthony`) was a red
herring: skills are namespaced, so the invocation is `/kerd:switch`. The *real*
bug the investigation found is that **Kerd's hooks were dead across eleven
repos**. The old mechanism (tend pastes a version-pinned plugin-cache path into
each repo's `settings.local.json`) is the anti-pattern the plugin docs name:
Claude Code garbage-collects old cache versions, so every pinned path dies the
moment its version is pruned — `docs/playbook.md` already documented this exact
GC-pin-rot gotcha (2026-07-11).

Fixed by moving to the standard mechanism, shipped v0.96.0:

- **`hooks/hooks.json`** created (pair, session-start, skill-complete) — the
  harness auto-registers it on enable, and `${CLAUDE_PLUGIN_ROOT}` resolves at
  runtime, so no repo ever pins a cache path again. Verified from live docs via a
  claude-code-guide agent (code.claude.com): the var expands in a plugin's own
  hooks.json but NOT in user settings.local.json.
- **`hooks/stop.sh` cut**; `hooks/hooks.template.json` retired (superseded).
- **`skills/tend/SKILL.md`** Category 9 rewritten — migrate/remove stale manual
  entries instead of wiring them; dev-repo exception dropped (would double-fire).
- **`skills/slainte/SKILL.md`** check 5 inverted — `hooks.json` is now the
  intended file, not an error.
- **De-referenced stop.sh** in `README.md` (+ v0.96.0 What's New entry, "three
  hooks", hook section rewritten for auto-load), `docs/state-contract.md`,
  `docs/design/time-awareness.md`, `docs/playbook.md` (GC-pin-rot gotcha marked
  resolved), `docs/requirements/categories.md` (SEC row — the outbound git-fetch
  is now auto-loaded for all users, sharpening the finding).
- **`tests/hooks_test.sh`** — stop tests removed, the template test re-aimed at
  `hooks.json`, session-start assertions updated for `/kerd:switch in`.
- **`hooks/session-start.sh`** — fixed its own bare `/switch in` → `/kerd:switch in`
  (same dead-command defect as stop.sh).
- **Version 0.95.0 → 0.96.0** in all three locations; frame at
  `docs/product/hooks-autoload.md` (route: problem, rigor: mvp).
- **Eleven consumer repos migrated** — dead hook entries stripped from each

## Gotchas

- **`${CLAUDE_PLUGIN_ROOT}` expands in a plugin's own `hooks/hooks.json` but NOT

## Insights

- **The reported symptom was not the bug.** "Unknown command: /switch" pointed at
  the command namespace; the actual failure was dead hooks from cache-version
  pinning. Chasing the red herring would have "fixed" nothing. The dead-command

  `/switch out`), closing the loop.

  fix for GC-pin-rot was an automated staleness check in tend. Auto-load removes
  the pinned path entirely — killing the bug class beats detecting-and-repairing
  it. The backlog row is now moot.

## Gotchas

- **`gh run list --commit <short-sha>` silently returns nothing** — it needs
  the full 40-char SHA. A poll loop that treats empty output as "not yet"
  spins forever on this; the first CI monitor this session did exactly that
  (silent-on-failure, the Monitor guidance's named failure mode). Match
  terminal states or use the full SHA.
- **A risk-ledger State cell is an exact enum token** — `accepted (with a
  parenthetical)` was refused by the slice gate. Qualifiers go in Evidence;
  the State cell carries only the legal token. The refuser catching its own
  author on the day it shipped.
- **A register statement whose FIRST line matches the meta shape
  (`**Word**: ...`) is refused as an unknown field** — ambiguity is refused,
  never guessed (documented in `parse_register`'s docstring). Reword the
  statement's opening or the block misparses by design.
