## Key Decisions

Full rationale in CONTEXT.md. **The approval fingerprint is ONE versioned
mechanism with artifact-specific canonical payloads** — existing requirements keep
the legacy statement-only payload byte-for-byte, `MSC` v1 hashes exactly
Statement · Measure · Baseline · Target, the byte stream is fixed centrally so an
alternate implementation cannot invent a different one, and **link stamps
targeting an `MSC` use the same full fingerprint**, never `req_statement_hash` ·
**reciprocal stamping stays separately owed**, because a richer target
fingerprint does not make protection bidirectional · **a ruling that changes a
mechanism invalidates every view describing it**, not only the view that was
wrong · **an assurance tally is counted by tense**, because counting a
dual-marked row as two lines makes proposed assurance read as present assurance ·
**the adjacent-wording rule binds on trees already keyed, not on the one being
keyed** — which is why the count correction was in scope rather than creep.
