## What Was Done

- **Added delegated execution to conductor (v0.62.0)** — the model-tiering feature Tony asked for: run a session on an expensive top-tier model (Fable) whose value is planning/hard problems, spend those tokens on the plan, and delegate the mechanical build to a cheaper model.
- **Switched the gate from auto-detect to an explicit toggle mid-session** (Tony's call). The first cut gated delegated mode on conductor "knowing" it was on a high-cost model — shaky (a skill can't reliably know its own model) and it ignored that Fable credits vary session to session. Replaced with `/kerd:conductor fable on|off` — an explicit assertion, **off by default**, **session-scoped** (rides the conductor line in `.active-modes` as `conductor: <phase> [fable]`, clears at close-out). Off, or on a Fable-less session, conductor runs inline on the active model as before.
- **`skills/conductor/SKILL.md` changes:**
  - New `## Usage` block documenting `/kerd:conductor` (inline) and `/kerd:conductor fable on|off` (toggle delegated execution).
  - Plan phase gained a "**Delegated execution — the spec is the contract**" block: the `fable` toggle gate, the spec file at `docs/plans/YYYY-MM-DD-<slug>-spec.md` (TODO `## Now` shrinks to a pointer), per-step `[fable]`/`[delegate]` tags approved at the plan gate, and a deliberately-higher bar for `[delegate]` steps (exact files, signatures, the *why*, verify command + expected output).

A subagent whose evidence fails acceptance counts against the 3-fix limit.

## Key Decisions

- **Delegated execution is an explicit toggle, not auto-detection** — `/kerd:conductor fable on|off`, off by default, session-scoped. Rejected the auto-detect gating: conductor can't reliably know its own model, and the real constraint is credit availability (session-variable), which the user asserts by flipping the toggle. Inline on the active model stays the default.
- **The spec is the contract** — a vague `[delegate]` step yields a confidently-wrong build from a cheaper model with no recourse, so spec quality is the safety mechanism and the whole justification for spending the expensive planning tokens.
- **Two step-tags, two dispatch modes** — tags are `[fable]`/`[delegate]` (actual implementer model picked at dispatch, not baked into the tag); dispatch is in-session subagents (default) or fresh-session handoff, chosen per session because Tony picked "both" at the design fork.
- **Top-level capability list left unchanged** — "session discipline" subsumes delegation; whether to surface model-tiered delegation as its own capability is logged as an open question in CONTEXT.md rather than decided.

## Insights

- **Delegation didn't need a new protocol** — it slotted into conductor's existing plan-approval gate. The spec-as-contract discipline is just conductor's existing "ban vague plan items" rule turned up to spec-grade, and the dispatch fork rides on the plan/execute split already there. The change is additive, not structural.
- **Building this inline (not delegated) was itself the correct call** — skill design is `[fable]`-type judgment work, exactly what the opt-in gate says *not* to delegate. Good confirmation the gate is scoped right: the feature's own construction is a negative example for it.

## Insights

- **Dogfooding delegation to build its own next increment worked cleanly** — the feature built itself through the flow it extends. Strong signal the v0.62.0 design holds under real use, not just on paper.
- **Observed, not assumed: small steps cost more to delegate than to do.** Writing a spec slice into a subagent prompt for steps 2–3 spent more planning-model tokens than the edits would have inline. Delegation economics favor bigger, genuinely-mechanical steps; the tags here were chosen to exercise the dispatch/evidence path cheaply, not because delegation paid off at this size. Honest caveat for anyone reading the dogfood as proof of savings — it proves the *mechanics*, not the economics.
